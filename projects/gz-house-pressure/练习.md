    r = annual_rate / 12
    n = years * 12

## 练习 3 · 找出代码里的 3 个 bug（20 分钟）

下面这段是我实际跑过、确认能跑出结果的版本，但里面有 3 个真实的 bug。
直接跑一遍就知道有问题——输出明显不对。

```python
def monthly_payment(principal, annual_rate, years):
    r = annual_rate / 12
    n = years * 12
    f = (1 + r) ** n
    return principal * r * f / (f - 1)

def calculate(price_yuan_per_sqm, area_sqm, down_ratio, rate, years, income_wan):
    total_wan = price_yuan_per_sqm * area_sqm / 10000.0
    down_wan = total_wan * down_ratio
    loan_wan = total_wan - down_wan
    pay_yuan = monthly_payment(loan_wan * 10000, rate, years)

    ratio = pay_yuan / income_wan          # ← bug 藏在这里附近

    if ratio < 0.3:
        level = "安全"
    elif ratio < 0.4:
        level = "吃紧"
    else:
        level = "超红线"
    return level

zones = [
    {"name": "越秀区", "price": 51766},
    {"name": "天河区", "price": 49473},
]

for z in zones:
    print(z["name"], calculate(z["price"], 89, 0.3, 0.03, 30, 1.2))
```

**你实际跑一下**，现在的输出是这样的：

```
越秀区 超红线
天河区 超红线
```

**问题：越秀和天河都是「超红线」，这个结论对吗？**
以 12000 元的月收入、89 平、30 年 3.0% 贷款算，越秀月供 **13,597 元**，
压力比 **113%**，确实严重超红线。
所以**输出的结论碰巧是对的，但过程完全错了**。

**这就是我要你抓的点**——**结果看着对，不代表代码对。**

**三个 bug 分别在：**

**Bug 1（计算）：单位混用**
函数参数叫 `income_wan`（万），但 `pay_yuan` 是元。
`pay_yuan / income_wan` 是拿「元」除以「万」，结果放大了 10000 倍。
正确算法算出比值 113，错误算法算出 **11,330.7**。

**这不是学术问题。** 如果你把这种代码拿去做真实的房贷测算，
算出来的月供会离谱到没人相信，工具直接失去价值。
**单位混用是金融编程里最高频的 bug，没有之一。**

**Bug 2（数据）：浮点数没有做精度处理**
`total_wan`、`down_wan`、`loan_wan` 全是浮点数。
实际算的时候会出现 `19488.000000001` 这种数字。
真实项目里金额必须明确精度——**金融代码里浮点数要转成整数分或者用 Decimal，
这是常识，面试必问。**

**Bug 3（显示）：只给了结论，没给数字**
只打印"超红线"，没打印月供、压力比、首付。
人看到"超红线"不知道超多少、为什么超，没法做决策。
**一个工具的输出必须让人看懂「为什么」，不只是「是什么」。**

**改完之后应该输出成这样**：

```
越秀区  89㎡  总价 460.7万  首付 138.2万  月供 13,597元  压力比 113%  超红线
天河区  89㎡  总价 440.3万  首付 132.1万  月供 12,995元  压力比 108%  超红线
```
