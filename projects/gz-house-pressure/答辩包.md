## Q1：等额本息月供公式是什么？为什么这么算？

**答案**：
```
月供 = P × r × (1+r)ⁿ / ((1+r)ⁿ − 1)
P = 贷款本金
r = 月利率 = 年利率 / 12
n = 总期数 = 年限 × 12
```

**为什么这么算（这段必须能说出来）**：

等额本息的意思是：**每个月还一样的钱**，还完为止。

核心是「现值等于终值」这个思想：
- 你现在拿到 P 万（这是负债，所以是支出）
- 你每个月还 A 元，一共还 n 个月
- 每个月的 A 折算回今天值多少钱？→ `A/(1+r) + A/(1+r)² + ... + A/(1+r)ⁿ`
- 这个累加是个**等比数列**，求和公式化简后就是上面的式子

**大白话版**：银行先算好，在你每期还的每一块钱里，拆成「本金」和「利息」两部分。
本金那部分是真正减少你欠款的，利息是银行赚的。
**前期利息占比高、后期本金占比高** —— 所以还到后面会明显轻松。

**面试可能追问**：
- 「那等额本金呢？」→ 等额本金是**每月还本金一样多**，利息按剩余本金算，所以月供**逐月递减**。
  总利息比等额本息少，但前期压力更大。等额本息月供恒定，收入稳定的人选它。
- 「银行默认哪个？」→ 商业贷款默认等额本息，因为它现金流可预测。

## Q2：为什么首付比例按 30% 算？

**答案**：因为这是主流商业贷款的最低首付要求（认房不认贷政策下的常规值），
也因为大部分人收入不高，杠杆再高银行不敢放。

**已知局限（诚实说）**：
- 实际首付比例受公积金缴存、征信记录、房龄影响
- 广州部分区域（如黄埔、番禺）首付比例可能更低
- 我没实现公积金+商贷的组合贷算法，这是已知缺口

**面试加分项**：主动说出局限，比被问出来强十倍。

## Q3：你的数据从哪来的？会不会是编的？

**这一题最重要，因为金融行业最忌讳编数据。**

**答案**：
数据来自 58同城广州二手房均价网（2026-10）和凤凰网房产广州的报道。
每个数字都在页面 `srcbar` 和 README 里标了来源和日期。

利率数据的来源更硬：
- 5年期以上 LPR 3.5%，央行 2026-09-20 报价，已连续 16 个月不变
- 广州首套商贷 3.0% = LPR − 50BP，这是我**查建行/中行网点口径**得到的，不是推算的
- 公积金 2.6%，来自广州公积金中心
- 2.7% 是渣打/汇丰的特惠价，但有门槛，不是普遍情况

**如果被追问「你怎么保证没编」**：
我说这句话 —— **「所有数字必须来自实际搜索，查不到就写未获取到，这是硬规则」**。
我给三个自动化任务写 prompt 时都加了这条约束，因为 AI 编财报数据是这个行业的致命伤。

## Q4：为什么只看「月供/收入」这一个指标？

**答案**：
因为这才是**真正的约束条件**。

绝对房价没有意义——广州 5 万/㎡ 和 2 万/㎡ 差 2.5 倍，
但月供应付能力只跟两件事有关：**你借多少** 和 **你的收入多少**。

「月供收入比」是三个东西的交集：
1. 银行批贷看它（超 40% 会被要求提高首付）
2. 你的生活质量由它决定（房贷吃掉 45% 收入 = 你不敢辞职、不敢生病）
3. 它是唯一跨区可比的指标

**行业惯例**：≤30% 安全，30–40% 吃紧但可接受，>40% 危险。

## Q5：这个项目的技术难点是什么？

**答案**（说实话，不装）：
这个项目本身技术不难，HTML + 原生 JS，零依赖。真正的难点不在代码，在两个地方：

**难点一：数据准确性**。
我一开始搜到两家不同网站给的房价差了一大截，聚汇数据和 58 同城的口径不一样。
处理方式是：**以单一数据源为主口径，其他源只做交叉参考，冲突就在文档里列出差异**。
金融数据混用不同口径是最容易出错的地方。

**难点二：不做绝对值判断**。
一开始我想做「推荐你去买哪个区」，后来发现这是错的——
这工具不该给建议，只该给**边界**。决策是人做的，工具只负责把数字摆清楚。

**这题的加分回答**：
「我不介意项目简单，我介意的是我知不知道自己简单。
我知道它的局限在哪、我知道它没算什么、我知道下一步该加什么。」

**额外准备**：如果你被问到「你怎么保证代码是对的」——
答：我用两种方式交叉验证过。JS 版和 Python Decimal 版算同一个 100 万 / 30 年 / 3%，
两边都是 4216.04 元，和银行口径一致。
**第一次我还把自己的校验基准值记错了（以为 20 年期应该是 5549，实际 5546），
所以我说「公式看起来对」不算数，得两套实现互相对得上才算。**

这一问是加分项，因为大部分候选人说不出自己验证过。

## Q6：为什么不用 React / Vue，纯原生写？

**答案**：
因为它是单页、无状态、零后端的工具，引入框架的收益（组件复用、状态管理）
在这里用不上。为了一个用一次就关掉的工具拉 300MB 依赖，是过度工程。

**但我也承认**：
如果后续要做「每月自动更新 + 数据可视化趋势」，那时候就该上框架了。
技术选型看场景，不看时髦程度。

## Q7：这个项目还有什么没做完？

**答案**（这个一定要有，面试官必问）：
- 组合贷（公积金+商贷）没实现，现在只能单选一种利率
- 没区分首套/二套，两者利率和首付比例都不同
- 没有反向求解器（反推「要上车某区，收入得涨到多少」）
- 房价是挂牌价不是成交价，实际成交低 5–10%，同区不同小区能差一倍
- 没做租售比对比 —— **这是最重要的缺口**，广州目前租售比只有 1.92%，
  年租金回报低于 2.7% 的房贷利率，财务上租房优于买房。这个我下一步做。

## 被问住时的万能兜底话术

真答不上来的时候，**不要硬编**。用这三句：

1. 「这个我没算过，我回去查一下明天回复您。」
2. 「这块我目前还没研究到，我理解的边界是……，但我不确定对不对。」
3. 「我知道这个和 A 不一样，但我说不出为什么——我想想再讲。」

**金融行业最看重的是诚实。** 编一个错答案 = 一票否决。
承认不知道 = 还有救。
